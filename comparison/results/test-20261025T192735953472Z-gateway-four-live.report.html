How to read the 95% confidence interval

On bank messages like these, the model's real accuracy is most likely within this interval.

Wilson score interval: if many independent samples of 154 messages were drawn from the same population and an interval built this way each time, about 95% of them would contain the true accuracy; the true accuracy is fixed, the interval varies.

These 154 messages are two per intent from the BANKING77 test set, a balanced rather than random sample, so the interval is approximate.

Refusals and unanswered messages count as wrong.

Message by message

All four models were given the same messages, so the fairest comparison looks at them one at a time, two models at a time. Each message falls in one of four groups: both right, only the first right, only the second right, or both wrong.

The messages both got right and those both got wrong say nothing about which model is better: they treated them the same. Only the split messages where exactly one model was right can tell them apart.

How lopsided is 14 to 10 for Jev and GPT-5.4-mini? If the two models were equally good, which one gets each of the 24 split messages right would be a coin flip. Flip 24 coins, and a split of 14 to 10 or more lopsided, either way, comes up about 54 times in 100 (this number is called the p-value: p = 0.5413). The usual bar for calling a difference clear is below 5 in 100. That is above the bar, so this sample does not show a clear difference. Being above the bar does not prove the two are equally good; more messages might show one. The name of this test, if you want to look it up: exact McNemar's test. Each of the six pairs is checked separately against the same bar, with no stricter bar for checking several pairs; this makes a chance finding somewhere among the six more likely. It does not establish an overall winner.

How this run was set up

RouteAll four through Vercel AI Gateway, a service that forwards requests to the model makers. The provider (the company answering) was fixed: Jev to TypeSafe, its maker; the other three to OpenAI, their maker.
What each was askedAll four got the same customer message, instruction and 77 labels: “Which banking customer-support intent does this customer message express? Choose the single best label.” Jev and Decisions API got a typed Choice question, which asks for one label from an allowed list. The two chat models got the same system message (an instruction about their task); replies had to use one of the 77 labels in a fixed data format (a strict JSON label schema).
How Jev picksJev gives labels probabilities (how likely it thinks each label is) and chooses the most probable label; its choice has no randomness or extra thinking setting.
Temperature and reasoningTemperature is how much chance goes into the choice of words; 0 takes the most likely next word piece rather than sampling (identical answers are not guaranteed). Reasoning effort controls how much internal thinking the chat model does; none requests no extra thinking. A token is a word piece. GPT-5.4-mini: temperature 0, reasoning none, 512-token answer limit; GPT-6 Luna: temperature 0, reasoning none, 512-token answer limit. Decisions API uses API-default reasoning (parameter omitted); no temperature is set.
OrderOne request at a time, in a balanced eight-message cycle; each model appears twice in each position.
RetriesUp to 6 attempts: if a service is busy, the run waits and tries again, the same way for every model. Waits increase from 1 to 16 seconds; a service’s requested wait is honoured, up to 30 seconds.
Frozen settingsFROZEN-gateway-four.json contains hashes refreshed for this export, not a new pre-test declaration. The saved run header retains the original run hashes.
Model versionThe version behind the typesafe-ai/jev alias cannot be confirmed.
